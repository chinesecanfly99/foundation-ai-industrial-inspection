# 03 技术架构与环境

## 技术路线

采用一个 Python 项目和共享推理核心。命令行、评估与 Gradio 调用相同模型、预处理和规则逻辑，防止网页与实验使用不同口径。

| 层次 | 选型 | 作用 |
| --- | --- | --- |
| 编辑与版本 | VS Code/PyCharm 二选一、Git | 开发、审阅与版本追踪 |
| 运行环境 | 独立 Python 虚拟环境；以本次实际验证版本为准 | 避免污染日常环境 |
| 图像与计算 | NumPy、Pillow；按实现使用 OpenCV/SciPy | 预处理、掩码与输入质量事实 |
| 基线 | 正常图片像素参考模型 | 无预训练下载的离线对照与联调 |
| CNN 方案 | PyTorch、torchvision 预训练网络 | 提取局部特征、正常特征记忆库和距离 |
| 评估 | 固定清单、逐图结果、指标实现 | 分开度量图像异常、像素定位和处置 |
| 界面 | Gradio | 浏览器上传图片与展示结果 |
| 配置与证据 | JSON/YAML、CSV、Markdown | 规则、模型元数据、实验与交接 |

Anomalib 是正式方法对照的可选扩展。当前简化模型不依赖它才能启动；若后续接入，要另外记录版本、精确算法与运行协议，不能把两个实现的结果混写。

## 模型说明

### B01 像素参考基线

仅用正常训练图片建立逐位置 RGB 均值与标准差，新图片与其比较得到标准化残差，再对三个通道的残差平方取均值并开方形成异常图。标准差设下限 0.035，防止低方差位置放大噪声。该方法计算简单、便于解释，但对位置、旋转和光照敏感；低成本基线的不足正是与 CNN 方案比较的依据。

### M01 局部特征记忆库

使用 torchvision ResNet18 的 `IMAGENET1K_V1` 预训练权重，提取 layer2/layer3，经局部平均、尺寸对齐与拼接构成 384 维局部特征；按固定 seed 与预算做均匀随机优先级采样。新特征与记忆库的最近欧氏距离除以特征维度平方根，再上采样成异常图。CNN 不微调，文档中的“拟合/训练”主要指记忆库构建与阈值校准。默认模型输入 128×128、记忆库预算 2,048，实际运行参数与数量以模型卡为准。

这是借鉴 [PatchCore](https://github.com/amazon-science/patchcore-inspection) 的教学实现。官方配置包含特定特征聚合、coreset 与异常打分设计；未实现这些细节时不宣称忠实复现，不引用官方性能作为本项目性能。

## 分数、阈值与可视化

- 模型原始分数是距离或偏离程度，不是已校准的缺陷概率。
- 图像级阈值用于异常判断，像素级阈值用于候选区域；两者分别校准、分别记录。
- 图像分数取异常图最高 1% 像素的均值。当前图像阈值为正常校准图像分数最大值乘 1.05，像素阈值为正常校准图在模型坐标下像素分数的 99.5% 分位数乘 1.05；阈值最低为 1e-6。两者都不使用官方 test 或缺陷掩码调节。
- 跨图片比较必须使用冻结尺度。若只为展示做每张图片独立的最小最大归一化，必须明确标成显示用，不能拿该颜色强度或归一化值作为统一决策阈值。
- 正常校准样本少时，最大值和高分位数估计不稳定；报告实际样本数与经验误报率，不承诺理论生产误报保证。乘 1.05 是预先设定的教学余量，未证明具有统计覆盖保证。

## 设备与离线运行

CPU 为必需路径；NVIDIA CUDA 是可选加速。首次安装和预训练权重下载需要联网，完成后演示应能从本地权重/模型文件加载。加载失败应明确报错，不静默换成随机初始化网络或另一种算法。macOS/MPS 只在有目标机器且实测成功时登记支持，不以本机 Windows 成功作兼容性结论。

Python、torch 与 torchvision 必须选择兼容组合。固定版本以实际安装后产生的依赖快照为依据；安装指引见根目录 README 与脚本，不将规划里的候选版本当成已安装事实。参考 [PyTorch 官方安装](https://pytorch.org/get-started/locally/)。

本次实际环境为Windows11（Python报告build22631）、Python3.11.1、NumPy2.4.6、Pillow11.3.0、OpenCV headless4.14.0.94、scikit-learn1.9.1、torch2.6.0+cpu、torchvision0.21.0+cpu、Gradio5.49.1、pytest8.4.2。Python位于项目`.venv/Scripts/python.exe`，实际设备为CPU，`cuda_available=false`；当前CPU发行包的结果不评价这台电脑物理GPU能力。环境依据为 `results/environment.json`。

## 建议保存的接口事实

每次结果应能追踪到 `input_id`、输入哈希、原图尺寸、实际设备、模型类型与哈希、数据清单版本、预处理尺寸、图像分数/阈值、像素阈值、异常面积比例、关注区重叠、输入质量、规则版本、触发规则及耗时。字段名以当前代码定义为准；接口变更时同步测试和导出说明。

原图坐标与预处理坐标必须明确区分。当前 pipeline 为保留比例的工作图（最长边不超过 1,024），模型内部再缩放为正方形；报告中的图尺寸/哈希对应工作图。关注区为工作图整图归一化矩形，初稿设为中心 `[0.2, 0.2, 0.8, 0.8]`。它是课程规则假设，需人工核对当前数据视角；不等同专业确定的瓶口区域。

## 目录职责

以根目录实际文件树为准：`src/` 保存模型、数据、规则和评估；`app/` 为界面；`scripts/` 为安装、数据和实验入口；`configs/` 保存配置；`tests/` 保存关键不变量检查；`data/` 保存本机数据/清单；`models/` 保存本机拟合产物；`results/` 保存实验结果；`docs/` 保存本规划。

大型数据、缓存、虚拟环境与大型模型不进入普通 Git 提交。公开仓库只保存可追踪清单、配置、源码、许可和必要小样例；数据与模型另行取得。
