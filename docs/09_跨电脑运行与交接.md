# 09 跨电脑运行与交接

## 交接目标

先让新电脑用 CPU 完成一次真正的单图输入到导出，再逐步恢复 CNN、真实数据评估和模型拟合。无需为了查看一张结果先下载全量数据、重新训练或配置 GPU。

用户指定最终目录为 `F:\Codex_file\Foudationai.groupwork`，但源代码不得写死该路径；其他电脑可以使用自己的目录。精确命令以根 README 和各入口 `--help` 为准。

当前本机已完成Python3.11.1 CPU环境、真实bottle两模型拟合与完整83图评估，已有可直接加载的 `models/bottle_pixel/` 与 `models/bottle_patch/`。数据清单支持相对根目录定位并有移动目录自动检查，但真实第二台电脑、macOS/GPU和断网复演尚未执行。交接方优先加载现有模型，无需先重训。

## 推荐复演顺序

1. 记录操作系统、架构、Python 路径、包版本、可用设备；建立新的独立环境，不直接拷贝另一台电脑的 `.venv`。
2. 按根 README 安装基础依赖，执行依赖检查和项目自检。
3. 使用固定样例和已有像素模型运行，检查输出文件实际可打开。
4. 安装配套 torch/torchvision，准备指定 CNN 骨干；再加载已有 CNN 模型。无 GPU 选择 CPU。
5. 用同样例核对两个模型的名称、阈值和元数据，不能把结果混用。
6. 启动 Gradio，用浏览器上传至少正常/缺陷/无效输入，下载结果。
7. 预装完成后断网复演；记录是否有未缓存的模型自动下载需求。
8. 需要正式研究时再取得 bottle 全部数据，复用冻结清单进行评估。

正式实验必须使用完全相同的数据内容/划分、模型、预处理、分数定义和规则版本。种子相同但原始文件不同，不等于同一实验。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 明明安装了包却提示缺失 | 启动与安装是否使用同一个 Python |
| torch/torchvision 导入错误 | 官方配套版本、CPU/CUDA 构建、旧环境冲突 |
| 离线启动仍下载 | 预训练骨干缓存/路径是否齐备；不要随机权重降级 |
| 换目录后找不到数据 | 是否用了相对路径或统一 data root，别写死原电脑盘符 |
| 异常图找不到掩码 | 类别目录与文件名匹配；缺标注要报错而非零掩码 |
| 正常图片看起来全是红色 | 是否每张图片独立拉伸色阶；决策是否仍使用冻结阈值 |
| 同图两电脑结果略不同 | 依赖、预处理、精度、设备、模型哈希；记录临界样例 |
| 端口占用 | 更换本地端口并记录，不终止无关进程 |
| 网页打开但预测失败 | 模型/配置/输出目录权限；服务器启动不等于功能通过 |
| Gradio启动自检502，但本机服务看似已启动 | 检查系统/环境HTTP代理是否转发了localhost；仅将localhost、127.0.0.1、::1加入NO_PROXY/no_proxy回环排除，保留已有条目，不必关闭全局代理 |
| 上传进度提示404 | 本次Gradio出现`upload_progress?upload_id=undefined`两次404；真实上传/预测/下载已验证可用。保留日志，若实际功能失败再按具体请求排查，不能据此宣称控制台零错误 |
| GPU 不能用 | 先用 CPU 完成，再单独诊断加速环境 |

## 应返回的交接证据

保存至本次独立结果目录：环境快照、准确安装与运行命令、退出状态、源码提交、输入/模型/配置哈希、单图输出、浏览器操作记录、离线结果、尚未执行项。新电脑数值允许合理浮点误差，事先约定容差；规则临界输出发生变化时单独说明。
