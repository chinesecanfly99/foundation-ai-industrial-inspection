# 阶段 06 规则与交互系统

## 目标

把视觉结果变成可追踪事实与辅助建议，完成同一推理核心的 Gradio 图片演示。

## 计划

规则角色定义输入质量、临界分数、异常面积与关注区规则及优先级；关注区必须符合 bottle 实际视角。界面角色展示原图、异常图、测量值、规则 ID 与导出。两位成员独立标注模拟处置标签后，实验角色才能运行 D00/D01 效果对照。

## 实施记录

2026-10-20：规则与Gradio初稿已实现。`demo-policy-v1`采用中心归一化关注区、亮度/清晰度、分数临界区、面积规则与首个匹配优先；保存所有规则condition/selected轨迹及策略版本/哈希。规则6个处置边界与无效事实检查已通过自动测试。真实两模型可供界面调用，浏览器上传/预测/导出验收进行中。没有独立业务处置标签。

## 验收

- [x] 事实和规则可单独测试，不依赖启动完整UI。
- [x] 规则边界、优先级和冲突例有轨迹，关键测试通过。
- [ ] 每个建议包含依据，且模型/规则版本与当前输入一致。
- [ ] 低质量输入有明确处理，计入端到端统计。
- [ ] 浏览器真实上传、预测、导出与错误输入经过验证。
- [ ] 多次切换样例不串图，清空输入不会保留旧结论。
- [ ] 处置协议和独立标签存在后才报告业务有效性。

## 证据

规则配置与版本、单元测试、单图 JSON、`results/ui_smoke.json`、实际浏览器记录。启动/API 测试与浏览器操作分别描述。业务标注文件与分歧记录单列保存。
