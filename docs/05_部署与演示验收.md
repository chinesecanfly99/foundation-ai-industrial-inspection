# 05 部署与演示验收

## 部署目标

初稿先在当前 Windows 电脑使用独立环境和 CPU 完成图片输入到结果导出。本机 Gradio 默认仅本地访问；需要组员通过局域网或公网访问时另行配置与测试。GPU、macOS、Linux、云端托管分别是额外环境，未经实测不写“已支持”。

当前已完成本机CPU模型拟合、保存加载与83图评估，33项关键自动测试和依赖检查通过。Gradio浏览器9项功能检查通过：合成正常/异常/黑图、两张真实bottle、空图、热图、JSON/CSV下载、规则与390px布局等，范围以`results/ui_smoke.json`为准。仍有非阻断上传进度404日志，下表的长期连续运行、新电脑、断网等不因此自动通过。

首次联网完成依赖、数据和预训练权重准备后，固定演示包应能够断网启动。像素基线应无需下载预训练权重。CNN 模型若缺少骨干文件，应报告准确缺失项，不偷偷改成随机权重。

## 演示脚本

1. 展示模型名称、实际设备、数据来源、规则版本。
2. 上传一张正常产品图：解释当前阈值下的建议及局限。
3. 上传一张明显缺陷图：展示原图、异常热力图、候选区域和分数。
4. 展示微小/困难缺陷，说明不确定性与复核。
5. 使用可追溯的低光或模糊版本，演示质量门控和重拍建议。
6. 显示一条决策轨迹，逐项说明事实、阈值、规则与最终建议。
7. 下载 JSON/图片输出，并在新输入后检查旧结果不会残留。
8. 展示一个失败案例，说明改进和当前限制。

整段时长按课程正式要求调整，不继承 CV 参考包的固定分钟数。备用录屏注明为预录；录屏不替代当前程序运行验收。

## 验收矩阵

实际结论写入`results/`与阶段文件；A02/A03的CPU模型路径和A04本机浏览器主要功能已通过。新电脑、离线、连续20次操作及更广输入格式仍单独验收，不由本机功能检查推断。

| ID | 测试 | 通过条件 |
| --- | --- | --- |
| A01 | 干净虚拟环境安装 | 不依赖开发者私有路径；依赖检查通过 |
| A02 | CPU 运行像素基线 | 正常/异常样例均产生合法结果；无需下载预训练权重 |
| A03 | CPU 运行 CNN 模型 | 加载指定模型，骨干/记忆库/阈值版本可追踪 |
| A04 | Gradio 页面实际操作 | 上传、预测、查看解释与下载可完成；不只测服务器响应 |
| A05 | 无模型、损坏文件、非图片 | 明确错误；应用可继续使用，不展示旧图结果 |
| A06 | 大图片、灰度、RGBA、极暗图 | 明确转换/限制；无崩溃与不合理坐标 |
| A07 | 连续处理至少 20 次 | 不串图，无异常持续资源增长 |
| A08 | 规则边界与冲突 | 阈值边界、低质量优先、关注区边界结果符合规范 |
| A09 | JSON/图片导出 | 可打开；字段、模型/规则版本和输入 ID 一致 |
| A10 | 预装后断网运行 | 不自动下载；两条模型路径按已准备条件运行 |
| A11 | 中文/空格目录 | 安装和推理不受路径空格、非 ASCII 字符影响 |
| A12 | 新电脑复演 | 另一位操作者从文档启动同一冻结版本 |
| A13 | 固定样例输出一致性 | 同配置且误差在约定容差内；临界样例差异列明 |
| A14 | 可选 GPU | 明确设备、无 CPU 假冒 GPU；与 CPU 结果合理一致 |

截图、启动日志、API 验证与真实浏览器操作属于不同证据，应写明分别执行了哪些。当前机器验证不能代替组员电脑复演。

## 发布包内容

源码、安装/启动脚本、经验证依赖、模型来源及哈希、冻结配置、固定演示样例、示例输出、故障排查、数据获取说明。虚拟环境不跨电脑复制；在目标机器重建。真实数据遵守原许可，原始 MVTec 大文件不放普通 Git 仓库。

建议保留两种准备方式：离线像素原型用于快速检查链路，CNN 正式演示包用于视觉研究。演示时明确当前采用哪种模型，不能把基线结果展示为 CNN 结果。
