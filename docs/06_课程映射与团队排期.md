# 06 课程映射与团队排期

## 课程要求现状

当前未收到 CDS521 完整原始评分表及最新提交格式，不能移用 CDS540 的权重、页数、展示时间和截止日期。以下为 Foundation of AI 学习目标的建议映射，取得 rubric 后逐项核对。

| 建议学习维度 | 本项目内容 | 可提交的证据 |
| --- | --- | --- |
| 问题形式化 | 输入图片到处置建议；正常外观定义 | 问题陈述、输入输出和适用边界 |
| 知识表示 | 质量、异常分数、面积、关注区等事实 | 事实结构、规则配置与示例 |
| 推理 | IF–THEN、优先级与冲突处理 | 推理轨迹、规则边界测试 |
| 机器学习与感知 | 正常样本学习、预训练特征、最近邻 | 两模型实现、数据清单和模型卡 |
| 实验设计 | 独立校准、冻结测试、对照和扰动 | 逐图预测、指标、失败分析 |
| 解释与责任边界 | 视觉证据、规则依据、人工复核 | 解释示例、标签协议和限制 |
| 工程协作 | 模块划分、版本管理、可复演 | 提交记录、交叉审阅、新电脑验收 |

即使老师最终不要求专家系统，明确规则层也能作为可解释决策设计；若要求使用 CLIPS/JESS 等指定工具，需单独调整推理实现和环境，不能假定 Python 条件分支自动满足所有评分要求。

## 六个可合并工作角色

角色是模块，不绑定成员身份或组长职责。实际人数未确认，4–6 人均可调整；成员人数较少可合并 A+B、D+E 等模块。角色认领与协调/提交责任由组内讨论。

| 角色 | 主要任务 | 交付物 | 交叉检查 |
| --- | --- | --- | --- |
| A 数据与许可 | 数据获取、清单、分割与掩码检查 | 数据卡、清单/哈希、QA | B 核对只用正常训练 |
| B 模型与基线 | 像素基线、CNN 记忆库、模型卡 | 配置、模型、拟合日志 | C 在同数据复跑 |
| C 实验与统计 | 冻结评估、预算对照、扰动、耗时 | 逐图结果、图表、失败案例 | A 核对泄漏与支持数 |
| D 规则与标注 | 处置协议、关注区、规则优先级 | 规则、标注、推理轨迹 | C 独立检查业务评估 |
| E 界面与复演 | Gradio、导出、安装与错误处理 | Demo、新电脑验收 | B 检查推理入口一致 |
| F 报告与整合 | 证据索引、报告、展示和问答 | 报告/PPT/提交检查 | 全员核对与各自解释模块 |

每个成员均参与报告审阅与演练。训练集中在一台电脑不等于其他成员无法贡献；配置、实验、标注、规则、审阅和复演都是可追踪的贡献。

## 相对六周排期

| 周次 | 主要工作 | 可验收里程碑 |
| --- | --- | --- |
| 第 1 周 | 范围确认、环境、合成闭环、数据来源 | CPU 最小闭环；rubric 待确认列表 |
| 第 2 周 | bottle 数据 QA、正常划分、像素基线 | 清单冻结；B01 可复跑 |
| 第 3 周 | CNN 记忆库、正常阈值、独立测试 | M01 模型卡；检测与定位对照 |
| 第 4 周 | 规则协议、独立标注、扰动与预算实验 | D00/D01 或明确标注不足；失败案例 |
| 第 5 周 | UI 完成、新电脑/离线验收、修复 | 固定演示包、性能与兼容证据 |
| 第 6 周 | 报告与图表定稿、PPT、演练与提交检查 | 文字与原始结果一致；全员可讲解 |

每周保留修错余量。若时间不足，先缩减第二类别、摄像头和云端扩展；保留一类完整协议、两个基线、规则追踪、独立评估与可复演。不能省掉测试独立性来追求更多功能。

本次已提前建立第1–3周主要工程与真实bottle基线，并不代表相应周次研究工作全部完成。剩余重点是规则独立标注、扰动/消融、失败分析、浏览器与新电脑验收和报告定稿；按实际完成内容重新认领，不必机械重复已验证实验。

## 汇报建议主线

“为什么需要正常样本异常检测 → 两种方法如何比较 → 检测后怎样推理 → 规则改变了什么 → 哪些情况仍会失败 → 课堂系统如何复演”。演示中的每个结论应能追溯到结果文件或清楚标为设计假设。

全员应能回答：为什么只用正常图训练；为什么不能用测试缺陷选阈值；距离为什么不是概率；简化模型和官方 PatchCore 有何区别；热力图为什么不能证明成因；规则标签如何独立获得；复核增加是否值得；CPU 速度在哪台电脑测得。
