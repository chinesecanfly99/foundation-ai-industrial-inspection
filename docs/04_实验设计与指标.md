# 04 数据协议、实验设计与指标

> 历史实验说明：本文主体记录2026-10-20首轮bottle协议与结果，292张数据、83张test及相应模型成绩均为该轮背景。通用评估原则继续适用；2026-10-26三类支持数、六模型结果和冻结协议见 [STATUS](STATUS.md) 与 [三类扩展执行规划](10_三类扩展执行规划.md)。不要把历史单类结果当作三类总成绩。

## 数据协议

首轮使用 [MVTec AD](https://www.mvtec.com/research-teaching/datasets/mvtec-ad) 的 bottle 类别。该基准区分无缺陷训练图像与含正常/缺陷的测试图像，并提供异常像素标注。实际数量由项目数据扫描输出，不把其他论文或教程的数量直接填成实测。

1. 原始图片与掩码保持不改，记录下载来源、许可、压缩包/图片哈希、类别及尺寸。
2. 官方 `train/good` 按固定 seed 约 80%/20% 分为正常训练与正常校准，实际比例允许整数舍入。先做内容重复检查，不把相同图片分到两边。
3. 仅正常训练集用于像素参考统计或 CNN 记忆库。正常校准集不加入记忆库，用于阈值和输入质量统计。
4. 官方 test 原样保留为测试，不用于骨干、采样数、规则阈值和分数阈值选择。缺陷名称可以用于事后分组报告，不能在推理时读取文件夹名泄漏标签。
5. 掩码必须按最近邻方式变换，避免插值产生伪标签；正常图像的掩码为零。缺失或无法配对的异常掩码明确报错，不当作正常。
6. 数据清单至少包含相对路径、原始 split、分配 split、缺陷类别、图像标签、mask 路径、sha256。记录清单哈希、生成程序版本与 seed。

跨分区精确重复必须移除或按组处理；若没有采集序列与实物身份，只能承认无法排除所有近重复/同物体相关性，不能宣称样本完全独立。后续若新增缺陷开发集，必须建立新协议并保留尚未使用的独立测试集。

本次实际清单为292张图，167张正常训练、42张正常校准，官方test83张（20正常、63异常）。解码并处理EXIF后的RGB像素哈希共有292个不同组，无精确重复；没有实物ID，仍无法排除同物体多次拍摄或近重复。数据从明确版本镜像获得并校验镜像LFS SHA256/大小，未校验原发布者归档哈希，详见 [08](08_来源与待确认事项.md)。

## 阈值原则

在运行测试前，固定正常校准方法、图像/像素分数定义、预处理、记忆库预算和质量规则阈值。当前图像分数是异常图 top 1% 像素均值，图像阈值为正常校准最大分数×1.05；像素阈值为正常校准的模型坐标像素分数 q0.995×1.05，两者下限 1e-6。像素阈值不等于控制独立图片误报率；像素之间相关，应另报告图像级误报。最大值×余量也不具有已证明的生产误报保证。

不能对每张测试图片按自己的最大值重新标定决策阈值。若测试后发现程序 bug，修复应建立新版本并明确曾查看测试结果；算法/规则方案变动应使用新的验证依据或把后续结论标为探索性。

## 实验矩阵

| ID | 方法/条件 | 目的 | 初稿要求 |
| --- | --- | --- | --- |
| S00 | 合成正常/异常样例 | 验证安装、接口、规则、导出与评估程序 | 必做；不代表真实工业效果 |
| B01 | 像素参考模型，正常训练 | 建立简单可解释对照 | 必做 |
| M01 | 预训练 CNN 局部记忆库，相同数据协议 | 比较特征方法与简单基线 | 必做 |
| C01 | M01 不同记忆库预算 | 检查内存/时间/质量取舍 | 正式项目推荐；一次只改预算 |
| D00 | 冻结模型，仅统一异常阈值 | 决策机制对照 | 有业务标签后运行 |
| D01 | 同模型，加质量门控、关注区与复核 | 检验规则带来的错误放行与负担变化 | 有业务标签后运行 |
| R01 | clean、亮度、模糊，同一测试图片 | 受控扰动敏感性 | 初稿至少提供入口，正式运行两类扰动 |
| P01 | CPU 批量单图推理与完整交互 | 性能与离线可用性 | 记录本机实测；新电脑单列 |

只有固定测试且完整运行的结果才能写作正式基线。若因资源只跑测试子集，应在 ID 中写明 smoke/subset，提供样本清单，不与全量结果直接比较。预算允许时对关键模型增加多个记忆库采样 seed，报告均值/范围，避免只挑最好一次。

本次B01/M01均已在完整83张test运行，seed42、输入128×128，CNN记忆库2,048。已见结果为像素AUROC0.9675/Recall0.7619，CNN AUROC0.9921/Recall0.7937，CNN仍漏13/63张异常。当前结果支持进一步研究，不能证明真实产线可自动放行。C01/R01/D00/D01未运行；不利用这次test表现调低阈值后再称独立改善。

## 检测和定位指标

| 指标 | 用途 | 口径 |
| --- | --- | --- |
| 图像 AUROC | 分数能否区分正常与异常 | 两类都存在才计算，缺一类记 N/A |
| 固定阈值 Precision/Recall/F1 | 冻结阈值下的实际取舍 | 异常为正类，列 TP/FP/TN/FN 和支持数 |
| 正常图误报率 | 复核负担基础 | FP / 正常测试图数 |
| 像素 AUROC | 定位排序能力 | 初稿统一128×128，跨图像像素合并计算；不是官方全分辨率 MVTec 评估 |
| 异常图 IoU/Dice | 冻结像素阈值的区域匹配 | 初稿128×128异常图均值；正常图误报面积作为后续补充 |
| 逐缺陷类型结果 | 检查是否偏向明显缺陷 | 分母与缺陷类型样本数必须同时提供 |

正常图的 GT/预测均为空时，若把 IoU 定为 1 再平均会抬高指标；初稿的定位均值仅对异常图汇总。微小缺陷被缩小消失时须在报告中说明。像素 AUROC 常受大面积正常背景影响，应与异常图 IoU、可视化一起解释。当前未实现 PRO/AUPRO；分辨率和协议不同，不直接与论文全分辨率或 AUPRO 成绩横比。

## 处置规则如何独立评估

MVTec 缺陷标注并不包含“可出厂”“应报废”或“重拍”标签。团队先写处置协议，再选固定小样本，由两位成员在不知道模型输出的条件下独立标注，记录冲突与仲裁。来源是团队的模拟业务定义，不是制造商质量标准。

标签可为通过、复核、不通过、重拍。预先说明哪些状态属于“自动处置”，哪些转人工；输出覆盖率与错误自动放行率时列出准确分母。至少报告：处置混淆矩阵、缺陷图被建议通过的比例、复核比例、重拍比例、自动处置覆盖率、标注一致性。比较 D00/D01 必须使用相同模型、输入和冻结配置。

规则单元测试只证明“程序按规则执行”。使用同一套规则自动生成所谓真值再评估属于循环验证，不能证明业务有效性。若没有独立标签，D00/D01 的效果表保持待实验。

## 扰动、耗时与失败案例

亮度、模糊图与 clean 使用同一清单；记录变换参数和 seed，不改测试标签、不重新校准。合成扰动不是真实夜间或失焦产线验证。质量门控拒绝的图片仍进入端到端统计，不能通过删掉困难输入人为提高剩余精度。

耗时分别记录：首次模型加载、热身后的推理调用、读取到规则/导出的完整处理。CPU 用墙钟；GPU 计时需要同步。固定线程数、设备、输入尺寸、样本数和模型哈希，报告 mean/p50/p95。首次下载模型时间与正常推理分开。

保存逐图预测后再选择至少 3 个误检、3 个漏检或最困难样例；样本不足时全列。每例附输入 ID、原图/GT/异常图、冻结阈值、触发规则和人工观察。不要把“像反光”写成已证明的模型因果解释。

## 每次实验的证据

`results/<experiment_id>/` 保存：解析后参数、实际命令、环境、数据清单哈希、模型/规则哈希、逐图预测、指标与支持数、输出可视化、运行日志和限制。报告表格直接从结果读取；待运行的表格用“待测”，不用演示数字填空。
