# 三类工业异常检测｜演示操作

本项目用正常样本建立视觉参考，寻找新图中偏离正常外观的位置，再用教学规则给出处置建议。真实类别为**瓶口、金属螺母、瓷砖表面**。

## 1. 打开页面

- PyCharm：运行 **Industrial Inspection Local**，访问 <http://127.0.0.1:7861/>。
- 启动脚本：双击 `start_windows.cmd`，访问 <http://127.0.0.1:7860/>。

以启动日志地址为准，保持启动进程开启。代码更新后先停止旧服务再启动。每台电脑的 `127.0.0.1` 只指向自己。

## 2. 先选择产品，再选择样例

| 产品 | 样例种类 | 适合解释什么 |
| --- | --- | --- |
| 瓶口 | 正常、大块破损、小缺口、污染或异物 | 明显破损与细小局部缺陷 |
| 金属螺母 | 正常、变形、颜色异常、翻面、划痕 | 结构、方向和表面变化 |
| 瓷砖表面 | 正常、裂纹、胶条残留、灰色划痕、油污、粗糙表面 | 纹理背景下的异常定位 |

样例名称来自数据集真实标注，模型输出异常分数与位置，**不自动命名缺陷类型**。同一类型的第1、第2张是不同图片，相似拍摄方式会使它们看起来接近。演示菜单的图片数量不等于训练和测试数据总量。

当前真实样例共75张：瓶口20、螺母25、瓷砖30，每种类型5张。完整真实数据974张，其中527正常训练、132正常校准、315独立测试；菜单只取其中一部分方便演示。

合成垫圈默认隐藏，可通过高级选项显示，只用于软件流程联调，不计入真实工业性能。

## 3. 两种模型分别做什么

| 页面模型 | 对应文件名 | 原理与用途 |
| --- | --- | --- |
| 特征记忆主模型 | `bottle_patch` / `metal_nut_patch` / `tile_patch` | ResNet18 提取局部特征，与该类正常特征库比较，生成异常分数与热图；默认使用 |
| 像素对比基线 | `bottle_pixel` / `metal_nut_pixel` / `tile_pixel` | 比较正常图各位置颜色统计，便于对照；对位置和光照更敏感 |
| 合成垫圈流程测试 | `synthetic_pixel` | 检查上传、热图、规则和下载，不代表工业检测水平 |

各类分别建模，不能用瓶口模型检查螺母。切换产品会更新模型和样例，并清除旧结果；上传自己的图片前也要选对类别。三类以外或不同拍摄条件的图片尚无效果依据。

## 4. 一次完整演示

1. 选瓶口正常图，使用主模型，点击“开始检测”，解释原图、热图、分数、阈值与建议。
2. 换大块破损图再检测，核对热图是否覆盖真实破损。
3. 切换金属螺母和瓷砖，分别展示正常图及一个缺陷图，说明相同算法为每类建立独立参考。
4. 展开逐条规则与完整记录，说明亮度、清晰度、异常面积与关注区重叠如何影响建议。
5. 下载当前 CSV 和 JSON，核对产品、模型、图片标识与当前输入一致。
6. 从完整测试结果选一个漏检或困难案例，展示阈值和模型的局限。可上传黑图演示“无法判定”：这意味着需重拍，不等于产品正常。

不承诺所有正常图都通过、所有缺陷图都拒收。演示样例带真实标签，但模型和规则建议可能出错，必须同时解释失败案例。

本轮已有可直接选择的主模型漏检分析样例：瓶口“小缺口 · 样例 000”（`broken_small_000`）、螺母“变形 · 样例 001”（`bent_001`）、瓷砖“粗糙表面 · 样例 000”（`rough_000`）。这三张在完整评估中的图像分数低于各自冻结阈值。页面规则还考虑面积和质量，因此最终建议应查看实际轨迹，不能把“图像级漏检”直接等同于规则一定给出“通过”。

## 5. 怎样比较主模型和基线

保持**同一产品、同一图片**，先运行主模型并下载记录，再切换像素基线运行。比较异常位置是否覆盖真实缺陷、是否将背景判为异常，以及分数与**各自阈值**的关系。

两个模型分数尺度不同，不能因为数值更大就说更好。少量演示不能替代完整测试；正式比较使用各类 `predictions.csv` 和 `metrics.json`，报告 AUROC、固定阈值召回、误报和定位指标。

人工缺陷掩码只用于评估与分析，不参与拟合、阈值选择或看完测试后调规则。页面热图不是人工标注。

## 6. 下载 CSV 和 JSON 为了什么

| 下载项 | 内容 | 用法 |
| --- | --- | --- |
| CSV 摘要 | **当前图片一行**：产品、模型、分数、阈值、异常面积、建议和理由等 | 用 Excel 整理演示对比；连续处理多张不会自动汇成一表 |
| JSON 报告 | 完整事实、逐条规则轨迹、采用规则、产品/模型/策略与图片校验等元数据 | 复核“为什么产生这个建议”、排查问题或供程序读取 |

CSV/JSON 不包含热图图片，需要时用热图组件的下载入口。完整批量实验的 `predictions.csv` 由命令行 `evaluate` 产生，和页面单图摘要不同。

换图、换模型或换产品后重新检测再下载；用 JSON 的 `image_sha256`、`product_category`、`model_id` 核对，避免拿上一张报告解释新图。

## 7. 讲解边界

分数不是缺陷概率；热图说明视觉差异，不诊断物理成因。瓶口、螺母中央矩形和瓷砖全图都是教学关注区；门槛未经工厂专家验证，也没有独立业务处置标签证明“拒收/复核”正确。

首次加载主模型可能较慢。本机默认 CPU，原有 GPU 环境未改动。三类实测成绩、浏览器通过范围和资产状态以 [STATUS](docs/STATUS.md) 为准；第二台电脑和断网演示仍需单独验收。

本轮本机已通过17项真实浏览器功能检查（三类主模型正常/缺陷、各类像素基线、报告下载、切换与错误恢复等），证据为 `results/three_products/ui/ui_smoke.json`；预览见 [三类页面](results/three_products/ui/preview.png)。功能通过不表示所有缺陷都能检出，仍需演示上述失败案例。
